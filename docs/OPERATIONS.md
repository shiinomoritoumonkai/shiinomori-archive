# 運用の手引き（docs/SPEC.md §12.3）

日々の更新は Drive のフォルダ整理と、GitHub Actions のボタン 1 つで済みます。ターミナルは要りません。

## 1. 更新の流れ

1. Drive でフォルダと写真を整理する（§2 の早見表）。
2. https://github.com/shiinomoritoumonkai/shiinomori-archive/actions → 左の「build-and-deploy」→ 右上の「Run workflow」→ 緑のボタン。
3. 3〜5 分で反映される。失敗したときは公開中のサイトが前の版のまま残る（空のサイトは公開されない）。
4. サイトを開き、フッターの「取り込みレポート」（`/#/report`）で枚数と警告を確認する。

`main` に push したときも同じように自動で反映されます。

「Run workflow」のときに **source** を `fixtures` にすると、Drive を読まずに仮データ（約 12,000 枚の仮画像）でデプロイします。合言葉は `demo-shiinomori-2026`（リポジトリに書いてある公開の値。仮データ用）。本番の Secrets が未設定でも動くので、サイトの形を確認するときに使います。実データに戻すときは `drive` で再実行します。

## 2. フォルダ規則の早見表（§4）

```
思惟の森アーカイブ/
├─ 1990年/                      ← 年。「1990」「1990年度」でもよい
│   ├─ 1990年_夏合宿/           ← 年_イベント名。区切りは _ - 空白のどれでも。「1990年夏合宿」も可
│   │    ├─ 表紙_集合写真.jpg   ← 名前が「表紙」で始まる 1 枚が、年表のトップの写真になる
│   │    ├─ オマルペ山/         ← スポット名と同じ名前のサブフォルダ → 中の写真に場所が付く
│   │    └─ 1日目/              ← それ以外のサブフォルダは、中身ごと「夏合宿」に入る
│   └─ 1990年_菅窪祭り/
├─ 1970年代/                    ← 年代までしか分からない写真
├─ 年不明/                      ← 年代も分からない写真
└─ _作業中/                     ← _ か . で始まる名前は読まれない
```

| やりたいこと | Drive での操作 |
|---|---|
| 写真を年表に載せる | その年・そのイベントのフォルダに入れる |
| 写真を外す | アーカイブの外へ移す。または `_` で始まるフォルダに入れる |
| 年やイベントを直す | フォルダを移動・改名する |
| 年表のトップの 1 枚を選ぶ | その写真の名前を `表紙` で始まるものに変える（例 `表紙.jpg`）。指定がなければ、その年の最初の横位置の写真が自動で選ばれる |
| 写真にキャプションを付ける | ファイルを右クリック →「詳細を表示」→「説明」欄に書く |
| イベントに説明文を付ける | イベントフォルダの「説明」欄に書く（年のページに出る） |
| その年の出来事を書く | 年フォルダの「説明」欄に書く（年のページに出る。年表のトップには出ない） |
| マップの写真を入れ替える | マップ用フォルダ（`青鹿寮/` など）の中身を入れ替える。新しい順に最大 16 枚が出る |

カテゴリ（春合宿・夏合宿・秋合宿・お祭り・その他）はイベント名から自動で決まります。規則は `config/events.json`。

### よく出る警告（レポート画面）

| コード | 意味 | 直し方 |
|---|---|---|
| `NO_YEAR` | 年が分からない場所に写真がある（取り込まれない） | 年フォルダの中へ移す。年が分からなければ `年不明/` へ |
| `NO_EVENT_FOLDER` | 年フォルダの直下に写真がある（「その他」で取り込む） | イベントフォルダを作って入れる |
| `BAD_YEAR_NAME` | `1988夏` のように、年の直後に区切りがなく年として読めない | `1988年_夏合宿` の形に改名する |
| `YEAR_MISMATCH` | 親と子で年が違う（子の年を採る） | 置き場所を確認する |
| `LOOKS_LIKE_COPY` | 名前が「のコピー」「(1)」で終わる | 中身を確認して、まとめるか改名する |
| `MULTIPLE_COVERS` | 「表紙」で始まる写真が 1 年に複数ある | 1 枚だけにする |
| `UNKNOWN_SPOT` | マップ用フォルダの名前がスポット一覧にない | `config/spots.json` の `name` と同じ名前にする |

## 3. 合言葉を変える

1. GitHub → Settings → Environments → production → `SITE_PASSWORD` を更新する（12 文字以上）。
2. 手元で `pnpm crypto:rotate` を実行し、`config/crypto.json` をコミットして push する（版番号が上がり、全員が再入力になる）。
3. 反映後、新しい合言葉を関係者に伝える。Drive 側の共有設定は変わらない（写真の URL を知っている人は引き続き見られる）。

## 4. スポットを足す・座標を取る

1. サイトで `/#/map?picker=1` を開き、地図の置きたい場所をクリックする。x・y（%）と雛形が出るので「コピー」。
2. `config/spots.json` に貼り、`id`（英字）、`name`（Drive のフォルダ名と一致させる）、`category`（`forest`／`dorm`／`community`／`event`／`scenery`）、`description` を埋める。読みがあれば `kana`。別名があれば `aliases`。
3. コミットして push。Drive のマップ用フォルダに `name` と同じ名前のフォルダを作って写真を入れる。

## 5. マップ画像を差し替える

1. 画像を `public/map/` に置く（幅 2,000〜3,000px の PNG か JPEG か SVG）。
2. `config/map.json` の `image`・`width`・`height` を合わせ、`initialCenter`（最初に中心にする位置、%）を調整する。
3. 画像が変わると座標がずれるので、§4 のピッカーで取り直す。

## 6. 困ったとき

| 症状 | 見るところ・対処 |
|---|---|
| 写真が出ない（灰色のまま） | `pnpm ingest verify` で共有設定を確認する（未ログイン状態で取得できるか）。Drive の「リンクを知っている全員」が外れていないか |
| 429 が多い（レポートではなくブラウザの開発者ツールで分かる） | `config/site.json` の `images.concurrency` を 6 → 3 に下げる |
| Drive の URL の形が変わった | `src/lib/photoUrl.ts` と `config/site.json` の `images` を直す。実測の記録は `docs/SPIKE.md` |
| Actions が失敗した | ログは件数だけ。手元で `pnpm ingest check` を実行すると詳細（フォルダ名）が見える |
| deploy ジョブだけが失敗した（「No artifacts named github-pages」など） | GitHub 側の一時的なエラー。失敗したジョブの「再実行」ではなく、「Run workflow」で**新しく実行**する（再実行だと成果物が 2 つになって拒否される） |
| 合言葉を入れても「違います」 | 直前に合言葉を変えた直後なら、反映（数分）を待つ。Safari で 7 日以上開いていないと再入力になるのは正常 |

## 7. 手元で動かす（開発者向け）

```sh
pnpm install
pnpm fixtures && SITE_PASSWORD=dev-password-12345 pnpm ingest build --from fixtures/listing.json
pnpm dev                 # 仮の画像で http://localhost:5173/shiinomori-archive/
pnpm test && pnpm e2e:prepare && pnpm e2e
pnpm ingest check        # 実 Drive（.env が必要）
```
